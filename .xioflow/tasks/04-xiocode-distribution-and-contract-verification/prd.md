# PRD: xiocode 最小发行版闭环与 8 项跨装配契约验收 (Task 04)

## 1. 需求背景与目标

### 1.1 核心证明命题
要证明 xioflow 是一个具有独立通用价值的受监督执行内核，而不是 xiocode 的私有内置库，**必须证明同一个内核在不同装配方式下的行为一致性与通用性**。

### 1.2 契约测试规范修正
- **测试比较标准**：断言只比较**相同操作条件下的状态规则、必要事件顺序与内核不变式**；
- **禁止脆弱时钟比较**：绝不比较真实时间墙时钟毫秒数或物理运行耗时，杜绝偶发性 Flaky 测试。

### 1.3 两个独立消费者
1. **消费者 A（无头 API 消费者）**：
   - 零 UI、零 LLM、无三件套 Markdown；
   - 仅通过公开 API 发起 `requestRun`、`submitOperation`、`cancelRun` 与 `resumeCrashedKernel`。
2. **消费者 B（xiocode 编程发行版）**：
   - 装配 Task 03 的默认三件套工作流组件与编程工具；
   - 包含极简 Agent Loop（Pi 范式：收集上下文 -> 调模型 -> 解析工具 -> 派发 Operation -> 推进三件套）；
   - 提供最小 CLI 入口。

## 2. 八项跨装配一致性契约测试 (Contract Tests)

两套消费者共同运行以下 8 项核心契约测试：

| 序号 | 契约测试项 | 核心断言与判定标准（规则/时序/不变式） |
|---|---|---|
| **1** | **错误命令启动** | 启动不存在的可执行文件立即显式失败，事件流中绝不产生假的 `running` 状态 |
| **2** | **大量输出压测** | 产生 50MB stdout 时进程顺畅退出，缓冲区排空，标记 `isTruncated = true` |
| **3** | **超时未确认停止保护** | 进程进入 `stopping` 且未确认退出前，其持有的资源排他锁绝不释放 |
| **4** | **受管资源冲突可诊断** | 两个 Operation 争抢同一资源，后发起者排队并输出持有者与等待时长诊断 |
| **5** | **不确定副作用防重放** | `indeterminate` 状态的操作在恢复时阻断自动重试，强制等待人工恢复指引 |
| **6** | **崩溃后保留可靠事实** | 掉电恢复后，已提交 SQLite 事务的事实在重启后 100% 完整重现 |
| **7** | **驱动缺失明确报错** | 缺少对应平台驱动能力时显式报错，严禁静默假成功 |
| **8** | **工作流无感替换** | 将三件套工作流替换为纯内存工作流，内核的 `KernelRunStatus` 状态规则与事件顺序完全一致 |

## 3. xiocode 最小发行版交互闭环

- **极简 Agent Loop**：
  - 遵循 Pi 极简循环，工具调用全部收敛为内核受监督 Operation；
  - 退出码与真实执行错误原样喂回模型上下文（Debug-First）；
- **CLI 最小命令**：
  - `xio task <create|start|verify|finish>`：基于三件套组件流转任务；
  - `xio run "<prompt>"`：直接在工作区运行编程任务。

---

## 4. 验收标准与交付物

1. **源代码交付（在 xiocode 仓库内）**：
   - `xiocode/src/runtime/agent-loop.ts`：xiocode 极简 Agent Loop；
   - `xiocode/src/cli/index.ts`：命令行 CLI 入口；
   - `tests/contract/headless-consumer.test.ts`：无头 API 消费者契约测试；
   - `tests/contract/xiocode-consumer.test.ts`：发行版装配契约测试。
2. **测试验证**：
   - 8 项跨装配契约测试 100% 通过；
   - 证明两个消费者零代码修改消费同一套内核。
