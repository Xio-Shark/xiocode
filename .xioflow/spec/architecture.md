# xioflow 内核与 xiocode 架构执行准则

> 本规约直接对齐根目录 [`ARCHITECTURE.md`](file:///Users/xioshark/code/projects/xiocode/ARCHITECTURE.md)，作为所有开发与验证任务的强制实施约束。

## 关键架构红线与核心协议
1. **严格区分共享内核与发行版**：
   - `xioflow` 负责机制（执行域、Task/Run/Operation 状态机、驱动抽象、资源仲裁、停止确认、SQLite 事务存储与崩溃恢复），零 UI 依赖，不绑定三件套或特定工作流；
   - `xiocode` 负责装配发行版（三件套工作流、Agent Loop、提示词/规约注入、模型适配与 CLI/TUI）。
2. **管理范围与异常影响**：
   - 默认工作区级**执行域（Execution Domain）**，同一时刻仅单活动所有者，不搞整机统一调度；
   - 发生异常时，**冻结冲突资源，允许已证明独立的运行继续**；区分“结果不确定”与“进程存活”。
3. **SQLite 事务存储与掉电保证**：
   - 控制事实、Run/Operation 状态与资源占用统一由 SQLite 事务（WAL + FULL/F_FULLFSYNC）持久化；
   - 严格区分控制事实持久化、受管产物持久化与外部副作用状态。
4. **四大核心运行协议**：
   - **启动协议**：先在 SQLite 登记操作意图与资源占用，再请求驱动启动并登记身份，严禁未登记即执行；
   - **资源恢复协议**：重启先获取域所有权，读取持久化占用重建隔离，核验现场后才开放安全新操作；
   - **Run 完成协议**：业务修复与执行事实分开，检查操作收尾、资源结清与无悬挂不确定态；
   - **恢复协议**：输入指纹 + 执行凭证 + 驱动后置核验，绝不凭文件单纯存在盲猜成功。
5. **停止确认流水线与驱动契约**：
   - 超时或取消先入 `stopping`，驱动确认停止才置为 `cancelled` 或 `timed_out`；未确认转为 `indeterminate`，严禁提前释放锁；
   - 平台驱动提供 `is_original_process` / `not_original_process` / `cannot_determine` 真实身份核验；
   - 有界输出排空：超限后标记 `isTruncated = true` 但持续读取流，等待 stdio `close` 设置有界超时。
6. **双消费者 8 项一致性契约测试**：
   - 无头 API 消费者与 xiocode 发行版共用同一内核导出，验证错误启动不产假运行、大输出不阻塞、未确认停止保留锁、不确定防重放、崩溃后可靠恢复等 8 项契约。
